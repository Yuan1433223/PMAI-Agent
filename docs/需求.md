# 需求：城市企业发现与招聘线索调查

2026年10月20日 · v0.2 草稿。本文件为项目当前需求依据；明确要求与候选实施分开。早期书稿与研究资料保留在独立研究区，不作为运行或理解本项目的必要依赖。

## 问题与收益

初始用户：希望在深圳寻找 Agent 开发、大模型应用及相关 FDE 机会的应届生。首位使用者为作者。

当前任务：从招聘推荐列表之外，发现更多企业，查明哪些有可进一步核查的相关岗位或业务线索。作者认为现有软件呈现范围不足；本项目不据此断言平台排序机制或全市实际岗位数量。

单次收益：得到一批此前未关注的企业及来源、招聘依据、未知项，能自行决定下一步。长期愿景是让其他城市、专业的用户也能复用，但不在首轮同时展开。

## 范围

明确做：企业发现、公开网页调查、按证据分层、保留来源和时间、允许用户核查与反馈。

明确不做：自动投递、代改简历、模拟面试、联系企业、保证录用、声称找全全市机会。

候选首轮：先处理本地官方样式名单的一小批企业，比较手工调查与工具帮助，再决定模型、编排和数据存储。样本选择不只按名称“像科技公司”或是否以深圳开头过滤。

## 最小任务

输入：本地企业名单、目标城市与方向、作者已有企业基线（尚未提供，不阻止名单质量检查）。

流程：登记来源 → 代码提取主体与页码 → 查公开业务和招聘材料 → 模型提出主体/岗位等语言判断 → 代码校验证据定位、契约与状态 → 输出分层结果与未知。职责及候选技术见 [开发设计](开发设计.md)，不把候选选型当作已确认需求。

输出：有招聘依据、待确认机会、值得关注企业；另存未完成、访问失败和明确不匹配。行业、资质、融资只作来源和业务标签，不自动推导稳定或应届友好。

反馈：作者核查是否新发现、是否值得继续了解、证据是否支持判断，记录下一步调查。工具与BOSS等现有渠道互补，发现企业后回招聘软件核查不算使用失败。

## 假设与首轮动作

假设：从名单出发的企业调查，比只使用当前推荐流发现更多值得进一步了解的机会。尚未验证，不承诺具体增量。

先做来源登记和小批次人工/工具调查，不先接入账号、不先搭全栈。模型可能帮助主体消歧、检索表述和证据分类；序号提取、原文定位、状态记录优先确定性处理。需要比较质量与成本后决定。

关键未知：本地名单的准确下载出处与文件状态；样本与调查预算；作者已有基线；“互联网企业”是否硬限制；应届毕业年份与岗位条件如何对齐。

这些未知不阻止当前建立模板、检查文件或设计首轮验证，但会限制招聘结论与用户收益判断。
