# 开发设计：企业发现与招聘线索调查

2026年10月20日 · v0.2 架构草案，供讨论，尚未实现。关联：[需求](需求.md) R-01～R-05；关系与约束见 [数据模型](数据模型.md)。

## 1. 最小闭环与分工

有限名单 → 单企业调查 → 有出处的招聘线索 → 作者核查 → 反馈回流。程序管理事实、状态与预算；模型处理语言歧义和候选判断。

| 环节 | 代码负责 | 模型负责 |
| --- | --- | --- |
| 文件进入（R-01） | PDF/DOCX适配、提取原文与位置、序号校验、去重提示；扫描件单独进入OCR分支 | 仅对解析异常或含义不明确的内容辅助解释，不逐页重读可解析文本 |
| 初始检索 | 用企业原名与任务模板生成查询，调用DeepSeek Search接口；URL去重、预算控制 | 有需要时扩展岗位别名和补查问题，不以模型记忆替代网页来源 |
| 网页进入 | 调用DeepSeek Fetch接口取得页面正文，保存返回快照、切片与定位；访问失败如实记录 | 在有限材料中筛选值得继续核查的页面与片段 |
| 主体与岗位判断（R-02） | 校验结构、身份引用、引文确实存在、字段来源与日期；检查字段是否属于同一岗位 | 解释企业别名、岗位职责、经验要求、地点及业务相关性；给出原文引用与未知 |
| 规则与状态（R-03/04） | 枚举、条件检查、状态转移、覆盖统计与失败处理 | 产生候选判断，不自行改规则或把缺失补成事实 |
| 结果与反馈（R-05） | 分层表格、证据详情、筛选、用户标注与导出 | 简短说明为什么值得看、还缺什么；不生成无依据推荐分 |

引用存在只能证明定位正确，不能自动证明语义支持。语义质量用模型评估与人工抽查验证。压缩上下文要保留否定词、经验要求、日期和岗位边界，不能只截关键词。

## 2. 框架与边界

候选组合：Python 确定性批处理 + 单企业 LangGraph 小图 + SQLite + Streamlit。先单用户、小批次运行，不先建微服务或通用多 Agent 平台。

```text
呈现层：Streamlit（筛选、核查、反馈）
应用层：批次任务 → 单企业调查图 → 结果查询
领域层：实体、岗位、证据契约、状态与规则
适配层：文件解析 / Search / Fetch / DeepSeek / 数据库
```

依赖向内：图调用领域规则与工具接口；数据库、模型、页面框架不成为领域概念。首次 UI 可直接调用应用服务；需要远端或独立前端时再增加 HTTP 接口，不先强制前后端分离。

### 模块边界（计划，不预建空目录）

```text
src/pmai_agent/                 # 首个实现切片开始后建立
  domain/                      # 实体、判断契约、状态与业务规则
  application/                 # 用例、工具/仓储接口、调查编排
  adapters/                    # DeepSeek、文件解析、SQLite的实现
  ui/                          # Streamlit页面，只调用应用用例
  bootstrap.py                 # 组装配置和适配器，避免领域层导入它们
tests/                         # 契约/解析样例、适配与流程检查
```

`domain` 不导入 LangGraph、Streamlit、模型SDK或数据库；`application` 使用接口而非具体供应商；`adapters` 实现接口，入口负责组装。图若保留，位于应用编排边界，不让图状态成为所有业务数据的唯一模型。不为每个简单函数创造接口，优先隔离外部I/O。

已有的是架构草案；代码结构、物理数据库schema、运行配置及故障行为仍需首个切片验证，不能把画图完成当作架构已验证。

```text
准备查询 → 搜索取页 → 语言判断 → 契约校验
                  ↑             ↓
                  └─ 有明确缺口且预算允许 ─┤
                                    └→ 保存 / 待核查 / 结束
```

LangGraph 候选理由是多步补查、持久化恢复及后续人工确认，不是“用了模型必须用图”。先保留各步骤普通函数；若试验只有一次取页加一次分类，小图可以退回顺序调用。

图状态保存调查ID、阶段、材料ID、缺口和计数，不装入全部页面或跨企业聊天历史。thread_id 使用本次 investigation_id。业务结果与 checkpoint 分开管理，写入需可重复执行；checkpoint 不保证外部调用或计费恰好一次。

## 3. 模型、工具与上下文

- 模型供应商按作者倾向先选 DeepSeek；模型ID、模式、prompt版本和每次用量均记录。默认从普通模式做抽取/分类，只有复杂消歧或补查决策再比较思考模式，不先认定后者更好。
- 输入是任务、主体候选及带ID的证据片段；输出是结构化 claim、evidence_refs、unknown_reasons、可选 next_query。无效JSON、空响应或契约不符有限纠正，仍失败标待核查。
- DeepSeek Search/Fetch 作为首个候选提供者：我们写薄API适配、缓存、定位和失败处理，不自建爬虫、站点抓取器或浏览器自动化。调用聊天模型本身不等于已经搜索。Search负责找页面，Fetch负责返回页面正文，语言模型负责理解所得材料；账户可用性与搜索质量尚未验证。
- 首轮保存Fetch返回的正文及来源，不宣称它是网站原始HTML或完整页面。接口取不到内容时标待核查，不自动扩建爬虫来绕过，也不补写不存在的内容。
- 取得的来源文件或页面正文快照留存；按公司、页面、任务去重和选片。普通关键词定位、段落与标题过滤先行；上下文不足时补取，记录未读范围，不把裁剪后的缺失当作不存在。
- 工具先定义普通接口：`parse_document`、`search_web`、`fetch_page`；统计直接SQL。需要外部助手复用时再加薄MCP包装，不把MCP当搜索引擎或数据库。
- 首轮不加向量库与LlamaIndex。SQLite是持久化工具，LlamaIndex是可选的检索/索引框架，二者不是数据量大小对应的替代品。模型利用检索材料作答已具有检索增强的思路，不必为使用RAG概念先搭向量库。
- 何时增加索引：来源材料反复复用、超出单次上下文，而当前SQL/关键词检索存在明确遗漏或成本问题；有固定查询与样例，能比较改进后再引入。阈值是任务上的不足与收益，不是达到某条数就自动升级。
- 网页内容是待分析数据，不作为运行指令；模型不能靠页面文字获得额外权限。每家与每批都有检索、取页、模型输出、时长和费用上限，达限写明缺口后结束。具体额度由小批次测量再定。

## 4. 数据建模：分开企业、岗位、证据与一次调查

| 实体 | 最小职责 |
| --- | --- |
| Company | 内部ID、候选名称与已核实别名；同名不自动合并 |
| DocumentSnapshot | 文件或网页、出处、获取时间、内容hash、解析版本与原文位置 |
| SourceEntry | 名单快照、原序号、原名、页码、对应企业或待消歧状态 |
| Investigation | 企业、任务/目标版本、模型与prompt版本、状态、预算消耗、起止时间 |
| JobLead | 企业下的一条岗位线索及其来源；标题、地点、应届信息不能跨岗位拼接 |
| Claim | 企业或岗位上的判断：字段、值、证据位置、推断/事实、未知原因与所属调查 |
| Feedback | 用户/实验、企业或岗位、是否原已知、是否值得继续了解、纠错与依据 |

运行状态、检索结果与语义结论分开：完成/失败/预算停止；有结果/未找到/无法访问/未调查；支持/反驳/未知。不能用一个 status 字符串代替三者。历史调查保留，不无条件覆盖旧结果；时效和有效性不等于抓取时间。

第一版计划一个业务SQLite文件、其中多张关联表，不是一张囊括所有字段的大表；取得的文本内容按hash保存，数据库记录位置。图检查点如需要则单独配置，不能与业务事实混为一谈。首切片只建立所需表，详见 [数据模型](数据模型.md)。未来多人并发写与服务化需求明确后再评估PostgreSQL；通过仓储接口隔离，不承诺更换数据库无需迁移。

## 5. 界面只服务核查

候选 Streamlit 原生数据表与布局：上方任务范围及进度，主体企业/岗位表，详情显示支持片段、原网页与未知，旁边标注反馈。不重画组件，不复用不匹配任务的聊天壳，也不做大型管理后台。

这能减少独立前端工作，但不保证达到作者期望的视觉观感。先用静态样本确认布局，再接真实调查。UI重渲染不能自动重复启动付费调查；任务由显式操作创建，状态保存后可再次打开。

R-05评估的是信息增量与核查成本；前端只是观察和反馈载体，界面漂亮不能替代有效性验证。

## 6. 作者基线与验证

保留三组企业：实验前已知集合 A、一次上午BOSS浏览新增集合 B、Agent调查集合 C。记录城市/岗位意图、浏览时间与渠道；不要求放弃BOSS，Agent发现后回BOSS核查是正常使用路径。

看 C 相对 A∪B 的新增企业，同时分别记录：只有业务线索、找到相关岗位、地点和应届证据齐全、作者愿意进一步了解。按企业去重，保留岗位级证据；不能用新增名称数替代有用机会数。

记录人工核查时间、错配、无法访问和费用。对两种渠道使用相近时间窗与明确预算；保留原始发现和交叉核查时间，避免把后续核查当成最初发现。同一作者的一次实验是试用证据，不代表对所有用户有效，也不能估计全市召回率。

实施顺序：名单与契约 → 小批次搜索/取页/模型判断及离线回放 → 表格核查界面 → 作者基线与反馈 → 再决定扩量、前端升级或MCP。未运行任何付费API、未安装依赖。

## 7. 核查的一手资料

- [Anthropic PDF Skill](https://github.com/anthropics/skills/blob/main/skills/pdf/SKILL.md)：复用现成工具和脚本化思路，不重复实现文件解析器。具体文件的 [许可](https://github.com/anthropics/skills/blob/main/skills/pdf/LICENSE.txt) 限制复制、衍生和分发，不能据GitHub可见就整包复制进本项目；可直接使用适用许可的底层库，独立组织所需适配。
- [DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/) 与 [思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)：JSON可解析不代表满足业务schema；含工具调用的思考模式有消息传回要求，接入时应验证适配器，不自行丢弃必需字段。
- [DeepSeek Search/Fetch](https://api-docs.deepseek.com/guides/search/)：独立搜索和取页接口，本设计未测试账户或费用额度，不把调用语言模型等同于已执行网页调查。
- [LangGraph持久化](https://docs.langchain.com/oss/python/langgraph/persistence)：用于核对状态保存与恢复能力；适配版本及故障行为仍需实现验证。
- [MCP架构](https://modelcontextprotocol.io/docs/learn/architecture)：能力包装与交换边界，不替代底层实现。
- [Streamlit数据表](https://docs.streamlit.io/develop/concepts/design/dataframes)：可复用表格、编辑和筛选相关能力；外观与任务体验仍需作者试用。
