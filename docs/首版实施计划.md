# 首版实施计划

2026-11-23 · 首版目标是在干净环境中让求职者免费完成一次“导入企业 → 调查 → 核查岗位原文 → 记录是否跟进”。下方执行记录维护实际验收结果。

## 阶段与提交

沿 S1 → S5 执行。表中入口和提交标题是工程约定，首次实现时将真实命令写入 README。每个阶段都从用户可操作的入口验收，再形成一个可独立审查的本地 commit。修复某阶段验收问题后重新验证，通过后继续。

| 阶段 | 代码交付 | 阶段验收 | 建议 commit |
| --- | --- | --- | --- |
| S1 名单可导入 | 建 Python 包、CLI、可复现依赖、忽略规则与 SQLite 初始迁移。支持样例文本型 PDF，保留来源、原序号、原名、页码和待消歧主体 | 从空库导入合成两页名单，按原序号查回每一行；重复导入数量不变，同名主体未误合并，断号或不可读页返回位置且无半批写入。真实原件另行核验 | `feat: import traceable company lists` |
| S2 单企业 Agent 可离线回放 | 实现调查状态、来源与模型接口、逐岗位证据、规则分层、定向补查、次数上限与恢复。CLI 提供 demo 和按 ID 查看结果 | 用固定响应演示一次“缺届别 → 补查 → 找到校招原文”；另测补查无果、错误引文、跨岗位引用、来源失败与中断恢复。停止原因可读，重复恢复不重复落库 | `feat: run evidence-backed investigations offline` |
| S3 真实公开材料可调查 | 接入本地推理服务（首选 Ollama，模型名称可配置）、一个无需账户的公开检索或目录适配器，以及招聘链接发现/正文读取。以公司全称查入口，核对归属后沿公开招聘链接限深、限页取详情，允许用户补充已知招聘 URL。保存来源、用量计数与错误，保持回放入口 | 用两家企业运行真实小批次，其中至少一家仅给企业原名，由程序发现入口，核对实际发现链接及至少一条真实岗位的字段和引文；无材料的企业保留未知。用回放覆盖站点不可达、正文为空、模型未启动、预算达限。若机器或来源不足，单列真实验收待办，不能用回放代签 | `feat: investigate public sources with local inference` |
| S4 求职者能核查与反馈 | 本地表格界面提供批次进度、筛选、岗位详情、引文、未知项、反馈和导出。CLI 和界面复用查询服务 | 从结果点回原文，记录一条纠错和一条值得跟进的岗位；关闭重开仍在。刷新不新建任务；导出后能按调查 ID 和来源定位岗位。失败和待调查企业可查 | `feat: review job evidence and save feedback` |
| S5 可交接的首版 | 补齐安装、模型配置、来源格式、样例、故障定位与自动化回归入口。校验公开样例的分发条件和仓库忽略规则 | 在干净环境按 README 安装、跑 demo、跑测试及 S3→S4 的真实流程；记录运行环境、命令和限制。作者试用时记录已知集合、招聘软件基线、Agent 新增且愿跟进的岗位及核查时间。缺个人基线只影响用户收益评估。公开分发前由维护者选定许可证并检查所选模型的分发条件 | `chore: verify and document the first usable release` |

## 实施取舍

S3 先用小样本验证无需账户的来源能否按企业名找到可读取的招聘入口，再固定适配器。查询执行后无匹配页记为“未找到入口”，来源不可用记为“无法访问”，尚未执行才记为“未调查”。用户提供 URL 可独立完成取页与判断，不能替代自动发现的验收。毕业届别是可选输入，行业默认作标签。无需在 S1 前确定这些参数的实际取值。

首版工程成型的标志是另一位使用者可以在本机完成 S1 至 S5 的操作，并对一条线索说明“为什么值得跟进，还缺什么”。作者收益实验和公开发布各自记录状态。
